# Neural Network Practice

Практическая реализация многопоточной и многопроцессорной обработки данных для аугментации на Python.

## Возможности

В проекте реализованы:

- многопоточное чтение файлов;
- архитектура Producer-Consumer;
- поток Producer для поиска файлов;
- несколько потоков Consumer для обработки файлов;
- использование queue.Queue для обмена данными между потоками;
- нормализация входных данных;
- общий счётчик обработанных файлов;
- синхронизация потоков с помощью threading.Lock;
- аугментация данных;
- поворот массива на 90 градусов;
- горизонтальное отражение;
- добавление шума;
- многопроцессорная обработка через multiprocessing.Pool;
- передача задач через apply_async();
- получение результатов через callback;
- CPU-bound benchmark;
- сравнение последовательной и многопроцессорной обработки;
- расчёт коэффициента ускорения;
- сохранение результатов в .npy;
- сохранение отчёта производительности в .json.

Требования
- Python 3.10+
- NumPy


Запуск: 

1. Установить зависимости:
# Устанавливаем NumPy и Pandas.
python -m pip install -r requirements.txt

2. Запуск проекта часть 3
# Запускаем многопоточную и многопроцессорную обработку.
python -m part3_augmentation.app.main

3. Результат

При запуске программы выполняется обработка файлов из каталога part3_augmentation/data.

Пример результата:

Обработано файлов: 3
Время многопоточного чтения: 0.010547 сек.
Количество процессов: 4
Время многопроцессорной аугментации: 0.310513 сек.
Размер итогового массива: (12, 3, 3)
Тип данных: float32


# Основные методы: 

FileProducer - сканирует каталог и помещает пути найденных файлов в очередь.

FileConsumer - получает пути файлов из очереди, загружает и нормализует данные.

augment_data() - выполняет аугментацию исходных массивов.

process_augmentation() - выполняет аугментацию в отдельном процессе.

cpu_bound_augmentation() - выполняет вычислительно затратные операции для CPU benchmark.

sequential_cpu_benchmark() - выполняет benchmark последовательно.

multiprocessing_cpu_benchmark() - выполняет benchmark с использованием нескольких процессов.

save_performance_report() - сохраняет результаты производительности в JSON.
